MODULE 02
Estimate Crafting Space
Technical Specification  ·  Phase 1: Functionality  →  Phase 2: UI/UX
What this space does: Holds all master data and design rules. Takes an enquiry as input. Automatically produces a first-draft estimate. A human reviews and approves. Approved estimate is formatted and served to client. Every action leaves a trail. SITC = Supply × 1.43
Build First  ·  Phase 1
Functionality
Data architecture, master records, logic engines, auto-generation, SITC validation, audit logging, and output production. All backend. Testable via API or admin panel — no polished UI required.
Build Second  ·  Phase 2
UI / UX
The interface layer — enquiry input form, auto-draft review and edit screen, master data management panels, estimate preview, format selector, dispatch flow, and audit timeline. Built on top of Phase 1 logic.

A Data Layer — The Master Records 8 entities  ·  All Phase 1
A.01
Master Material Register
Phase 1

Single source of truth for every fire safety material Greenberg supplies or installs. Every other master links back to this register via material_code.

  • material_codeSTRUnique. E.g. FAS-SMK-001, HYD-PIPE-65, EXT-ABC-04
  • material_nameSTRFull name. E.g. Smoke Detector (Photoelectric)
  • system_typeENUMFAS | Hydrant | Sprinkler | Extinguisher | Suppression | Common
  • categoryENUMDetector | Panel | Cable | Pipe | Valve | Pump | Fitting | Extinguisher | Accessory | Signage
  • unit_of_measureENUMNo. | Metre | Set | Kg | Litre | Lot
  • activeBOOLCurrently in use in BOQs — inactive items excluded from generation
A.02
Master Spec Data
Phase 1

Technical specifications for each material — standard, rating, size, certifications. Linked 1:1 to the Material Register. Used in BOQ description and compliance notes.

  • material_codeFKLinks to A.01 Master Material Register
  • applicable_standardENUMIS | NBC 2016 | NFPA | UL Listed | FM Approved | Client Spec
  • ratingSTRE.g. 24V DC 20mA, PN16, Class E, 4 kg capacity
  • sizeSTRE.g. 65mm dia, 4C×1.5sqmm, 150mm dia
  • certificationsARRArray — BIS | CE | UL | FM | LPCB
  • compliance_notesSTRFree text — clause reference, local fire authority notes
A.03
Makes & Brand Database
Phase 1

Approved brands for each material, tiered by quality. Pricing engine picks the right make based on client's preference — Premium, Standard, or Economy.

  • make_codeSTRUnique. E.g. HON-FAS, AGN-EXT, SIE-DET
  • material_codeFKLinks to A.01 — which material this make applies to
  • brand_nameSTRE.g. Honeywell, Siemens, Notifier, Agni, Supremex, Minimax
  • tierENUMPremium | Standard | Economy
  • approval_statusENUMApproved | Conditional | Blacklisted
  • notesSTRConditions, specific product lines, or known exclusions
A.04
Pricing Database
Phase 1

Live and historical buy/sell rates per material per make. Every rate change creates a new versioned record — old rates are never deleted so past quotes remain fully re-traceable.

  • price_idSTRAuto-generated unique ID per rate entry
  • material_codeFKLinks to A.01
  • make_codeFKLinks to A.03 — rate is make-specific
  • buying_rateNUM₹ per unit — what Greenberg pays the supplier
  • selling_rateNUM₹ per unit — quoted to client (buying + margin)
  • effective_fromDATERate valid from this date
  • effective_toDATENULL = currently active. Filled when superseded by new rate.
  • created_bySTRUser who entered this rate — part of audit chain
A.05
Installation Rates Master
Phase 1

Labour rate for every installation activity. Together with supply rates, this computes SITC at line-item level. The 1.43 blended ratio is validated against the sum of these line rates.

  • rate_codeSTRUnique. E.g. INST-DET-001, INST-PIPE-65
  • descriptionSTRE.g. Supply & Install Smoke Detector (Photoelectric)
  • system_typeENUMFAS | Hydrant | Sprinkler | Extinguisher | Common
  • linked_materialFKOptional — links to A.01 for material-specific install rates
  • rateNUM₹ per unit of activity
  • unitENUMPer No. | Per Metre | Per Set | Per Floor | Lumpsum
  • effective_fromDATERate valid from this date — new record created on change
A.06
Design Logic Rules Engine
Phase 1

Parametric rules that translate building input parameters into a Bill of Materials. The intelligence core of the module. Rules built and maintained by Greenberg based on IS, NBC, and NFPA requirements.

  • rule_codeSTRUnique. E.g. DL-FAS-001, DL-HYD-003, DL-SPR-002
  • system_typeENUMWhich fire system this rule applies to
  • conditionEXPRTrigger — e.g. building_type=Commercial AND floor_area <= 500
  • output_material_codeFKWhat material this rule produces — links to A.01
  • quantity_formulaEXPRE.g. CEIL(floor_area / 60) for smoke detectors per IS 2189
  • standard_referenceSTREngineering basis — IS clause, NBC table, or NFPA section cited
A.07
Profit Margin Matrix
Phase 1

Target and floor margins per project tier. Pricing engine applies these automatically. Any estimate falling below floor margin is flagged and cannot be approved without explicit authorization.

  • tierENUM1 | 2 | 3 | 4 — mapped from estimated project value
  • tier_labelSTRE.g. Tier 1: Sub ₹5L, Tier 2: ₹5L–₹20L
  • target_margin_pctNUMDefault margin applied by the pricing engine
  • floor_margin_pctNUMMinimum acceptable — below this triggers approval gate
  • discount_authorityENUMWho can approve below-floor margin — MD | GM | Self
A.08
Enquiry Input Schema
Phase 1

Standardized input record that triggers the entire generation engine. Every estimate must trace back to a valid, complete enquiry record. Auto-generates the enquiry_id.

  • enquiry_idSTRAuto-generated. Format: GBE-ENQ-2025-001
  • client_nameSTRClient or developer name
  • project_nameSTRBuilding or project name
  • building_typeENUMResidential | Commercial | Industrial | Institutional | Mixed
  • floors_aboveNUMStoreys above ground level
  • floor_area_sqmNUMPer floor — if uneven, per zone with separate inputs
  • systems_requiredARRArray: [FAS, Hydrant, Sprinkler, Extinguisher, Suppression]
  • make_preferenceENUMPremium | Standard | Economy | As per Greenberg
  • project_tierENUM1–4 auto-suggested from estimated value, manually editable
B Logic Engines 3 engines  ·  All Phase 1
B.01
Design Logic Engine
Phase 1
Inputs
  • Enquiry parameters (A.08)
  • Design Rules database (A.06)
  • Applicable standard selected
Process
  • Match building params against rule conditions
  • Execute quantity formula per matched rule
  • Repeat per system type requested
Output
  • Bill of Materials: item_code, name, qty, unit — per system
// Example rule execution IF system = FAS AND bldg = Commercial smoke_det = CEIL(floor_area / 60) heat_det = CEIL(floor_area / 30) // per IS 2189 spacing tables
B.02
Pricing Engine
Phase 1
Inputs
  • BOM from B.01
  • Pricing Database — A.04
  • Installation Rates — A.05
  • Margin Matrix — A.07
  • Make preference from A.08
Process
  • Lookup selling rate: item + make tier
  • Lookup install rate per activity
  • Apply tier margin to supply rate
  • Compute line totals
Output
  • Line-item estimate: supply amt, install amt, SITC, line total
// Per line computation supply_amt = qty × selling_rate install_amt = qty × install_rate line_SITC = supply_amt + install_amt
B.03
SITC Validation
Phase 1
Inputs
  • Total supply amount from B.02
  • Total SITC amount from B.02
  • Target ratio: 1.43
Process
  • Calculate actual blended ratio
  • Compare against 1.43 target
  • Flag if deviation exceeds 5%
Output
  • PASS or ALERT status stored on estimate with actual ratio
// Validation gate ratio = total_SITC / total_supply IF ratio < 1.35 OR ratio > 1.51 → FLAG for human review → block auto-approval
C Output Formats Format A: Phase 1  ·  Format B: Phase 2
FORMAT A  ·  PHASE 1
Greenberg Standard Format
Phase 1

Greenberg's own BOQ structure, auto-generated from the approved estimate. PDF and Excel output. No manual formatting work required on the team's end.

  • 01Company letterhead — name, CIN, GSTIN, NEBOSH/NFPA credentials, contact
  • 02Estimate header — estimate no., date, validity period, client, project name
  • 03Systems summary — what is included and indicative value
  • 04Line items by system section — one section per system type
  • 05Per line: item code | description | make | qty | unit | supply rate | install rate | SITC rate | line amount
  • 06Sub-total per system section
  • 07Grand summary — total supply, total installation, total SITC, blended ratio
  • 08Final quoted amount with applicable tax breakout
  • 09Commercial terms — payment schedule, validity, scope inclusions and exclusions
FORMAT B  ·  PHASE 2
Client Provided Format
Phase 2

Client uploads their own BOQ template. System maps Greenberg's line items into the client's column structure and populates it automatically. Requires a mapping UI built in Phase 2.

  • 01Client uploads their BOQ template — Excel or PDF
  • 02Template parser identifies columns, rows, and structure
  • 03Mapping interface — Greenberg field linked to client column
  • 04Mapping saved as reusable template per client — mapped once, reused always
  • 05Auto-population of client format from approved estimate data
  • 06Human review of mapped output before dispatch
  • 07Export as Excel maintaining client's original formatting and structure
D Audit & Trail Every action logged  ·  Phase 1  ·  Never deleted
Complete Event Log — Enquiry Received to Estimate Dispatched
stored per estimate_id  ·  full timeline accessible any time  ·  records never modified or deleted
Phase 1
  • ENQ_CREATEDEnquiry logged with all input parameters, source, received_by, and timestamp.
  • GEN_STARTEDAuto-generation triggered. Rules version and pricing snapshot date locked at this moment.
  • RULE_APPLIEDEach design rule executed — rule_code, condition matched, qty formula result, material added to BOM.
  • PRICE_APPLIEDRates pulled — price_id used, make selected, buying and selling rates, date effective.
  • SITC_VALIDATEDBlended ratio computed and stored. PASS or ALERT status recorded with actual ratio value.
  • DRAFT_v1_CREATEDFirst draft locked as version 1. Immutable after this point — all edits create new version records.
  • REVIEW_STARTEDHuman reviewer identified. Session start timestamp recorded.
  • LINE_EDITEDField changed — field_name, old_value, new_value, optional reason note, actor, timestamp.
  • LINE_ADDEDNew line item added manually — full item detail, who added, reason for manual addition.
  • LINE_REMOVEDItem removed — item detail preserved in log, reason recorded, item not deleted from database.
  • EST_APPROVEDFinal version locked by approver. No further edits possible without triggering EST_REVISED.
  • OUTPUT_GENERATEDFormat type (A or B), output filename, generated_by, generation timestamp.
  • EST_DISPATCHEDSent to client — channel (email / WhatsApp / portal), recipient, dispatch timestamp.
  • EST_REVISEDNew version triggered — reason (client request / scope change). Prior version archived, new version cycle begins.
Each event record:  event_type · estimate_id · version · actor · timestamp · payload
Timeline view: all events for any estimate in chronological order — from ENQ_CREATED to EST_DISPATCHED.
Version compare: any two estimate versions diffable side-by-side — what changed, added, or removed.
